# 발표 스크립트

## 프로젝트 개요

우리 프로젝트는 K League 공식 공개 페이지에서 확인 가능한 K League 1/2 active 선수단을 기반으로 만든 DB 중심 이적시장/스쿼드 운영 시뮬레이터입니다.

사용자는 구단을 선택하고 포지션 약점, 예산, 선수단 뎁스, 추천 영입 후보를 확인할 수 있습니다. 영입을 실행하면 선수 소속, 계약, 구단 예산, 이적 기록, 감사 로그가 MySQL 안에서 트랜잭션으로 함께 변경됩니다.

몸값은 임의로 산정하지 않았습니다. K League 공식 페이지에는 market value 필드가 없기 때문에 선수단과 기록은 K League 공식 데이터를 사용하고, 선수 몸값은 Transfermarkt K League 1/2 공개 market value만 사용했습니다. 공식 영문명과 구단이 일치하거나 구단/나이/국적/포지션이 유일하게 매칭되는 선수만 기본 이적시장에 올렸습니다.

## DB 설계 포인트

1. `players`와 `player_stats`를 분리해 선수 기본 정보와 능력치를 정규화했습니다.
2. `contracts`는 선수와 구단 사이의 계약 이력을 저장합니다.
3. `transfer_market`은 실제 market value가 확인된 기본 매물을 관리합니다.
4. `transfer_history`는 영입, 방출, 자유계약 같은 이적 이벤트를 시즌 단위로 기록합니다.
5. `seasons`와 `squad_battles`는 배틀 결과와 시즌 순위를 연결합니다.
6. `audit_logs`는 트리거로 생성되는 변경 이력입니다.
7. `views`를 통해 예산, 스쿼드 점수, 포지션 약점, 추천 선수 목록을 쉽게 조회합니다.

## 핵심 기능

- 구단별 포지션 뎁스를 리그 평균과 비교해 약점을 찾습니다.
- 추천 시스템은 선수 오버롤, 포지션 약점, 예산 적합도, Transfermarkt 몸값 대비 이적료 효율, 나이를 조합합니다.
- 영입 시 판매 구단이 최소 11명을 유지하는지 검증합니다.
- 기본 이적시장 매물은 실제 Transfermarkt value가 매칭된 선수만 표시합니다.
- 포메이션 배틀은 각 팀이 최소 11명 이상일 때만 가능하고, 주전 11명 중심으로 계산합니다.
- 후보 선수는 상위 7명만 낮은 비중으로 반영해 후보 수가 많은 팀이 자동으로 과대평가되지 않게 했습니다.
- 시즌 종료/새 시즌 시작으로 순위와 기록을 관리할 수 있습니다.

## 강조할 DB 기능

- CHECK 제약 조건
- Foreign Key

- Transaction / Rollback
- Window Function
- Audit Log

## 발표 문장

선수 영입은 단순 UPDATE가 아닙니다. 계약, 소속, 예산, 이적 기록, 감사 로그가 동시에 바뀌는 작업이므로 저장 프로시저 안에서 하나의 트랜잭션으로 묶었습니다. 하나라도 실패하면 전체 작업이 취소됩니다.

또한 몸값은 내부 공식으로 만들지 않았습니다. Transfermarkt에 공개된 market value를 그대로 가져오고, K League 공식 영문명과 비교해 확실히 매칭되는 선수에게만 적용했습니다. 매칭되지 않은 선수는 임의 값을 넣지 않아 데이터 신뢰도를 유지했습니다.

마지막으로 팀 전력은 전체 선수 평균이 아니라 주전 11명과 제한된 후보 기여만 반영합니다. 그래서 후보가 많은 팀이 자동으로 유리해지는 문제를 줄이고, 실제 감독이 보는 스쿼드 운영 관점에 더 가깝게 만들었습니다.
